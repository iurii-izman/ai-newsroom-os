## Шаг 2 — Найди проблемы

Найди:

- внутренние противоречия;
- дублирование;
- неоднозначные формулировки;
- непроверяемые требования;
- требования без acceptance criteria;
- требования без владельца;
- архитектурные решения без причины;
- сущности, не используемые в F0;
- скрытые зависимости между фазами;
- отсутствующие failure scenarios;
- требования, которые ведут к scope creep;
- требования, которые невозможно выполнить детерминированно;
- требования, которые могут привести к data loss;
- требования, создающие лишние зависимости;
- требования, создающие ложную уверенность;

Не ограничивайся очевидными замечаниями.

---

## Шаг 3 — Для каждой проблемы дай полный разбор

Для каждого finding объясни:

1. что именно не так;
2. где это находится;
3. почему это важно;
4. какой реальный отказ может произойти;
5. насколько проблема критична;
6. какое минимальное изменение исправляет её;
7. нужно ли исправлять сейчас или позже;
8. не создаст ли исправление новую сложность.

```text

→ Source

→ Mock Story Package
→ JSON/Markdown export
```

- какие переходы state machine нужны;
